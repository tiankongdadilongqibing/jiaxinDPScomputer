问题 1:狂気 ×1.5 没被识别
  结论:PASS(已修)。受击方狂気 = 被伤害 ×1.5,取实测值,不是 ratio/100。
  证据等级:实测。干净格 0.9996->1.4954(×1.4961)、0.9965->1.5011(×1.5063);
            合并受控倍率 1.4886(无狂気 58.7M vs 有狂気 45.2M)。
  落地:Chain.cs 折进 vicMod;开关 General/MadnessVictim;每击导出 victimMadnessOn。
  反证:victimMadnessOn 必须恒等于 ("狂気" in victimStatuses),否则是检测 bug。

问题 2:P0 的 ×1.15²
  结论:PASS(已修)。根因不是倍率模型,是规则文本里的「と」连接词没被认出来。
  证据等级:实测(导出语料 + 代码路径)。
    * 旧队 183213:[ド・マリニーの掛け時計] 全场 folded 0 / parked 960,
      而那些命中残差恰好 1.3225 = 1.15²(809 击)。
    * 对照:毒の短剣(毒状態の敵に対して)折 2700;海魔の残滓(毒/火傷状態)折 5510。
    * 三处病灶(StatusTokens 停/连词、JudgeClause それぞれ 叠加要求 stHits>1、
      EvalConditions 残留「毒」撞关键词表)叠在一起 => 整条规则一分不折。
  落地:抽出 Model/ClauseStatusRun.cs(纯函数),由 recon_probe 执行 + 变异测试钉住。

顺带结案:1.9 / 1.65 / 1.85 不是 P0
  结论:是「推断出来的会心」。残差恒等于 critDamageRate/100。
    190->1.9(649 击)、165->1.65(76)、185->1.85(2);同一 critDamageRate 池里
    一部分 1.0、一部分 1.9 => 这是「这一击有没有掷中」。
  IsCritExplained(CritRate>0 且 CritDamageRate>100 且误差<=0.002)已在收,计入 exactWithCrit。
  仍然欠着的:CritObserved = 0/6220,会心只能推断 => P3,不是 P0,也不靠探针解决。
