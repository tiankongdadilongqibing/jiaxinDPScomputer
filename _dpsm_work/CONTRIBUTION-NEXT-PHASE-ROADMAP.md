## 1. 核心建议

下一阶段应从“能展示贡献表”转向“能可靠支持配队决策”。推荐顺序：

**N0 最新版本验收闭环 → N1 验证与比较契约 → N2 可信跨场比较 → N5 配队报告。**

同时开展 **N3 身份与实验元数据设计**、**N4 攻击力归因敏感性研究**；N6 残差研究、N7 产品化按证据和收益推进。

不要为了追求看似完整的模型，先去增加暴击归因、治疗折伤害、自动换人模拟或训练场专用公式。当前最大的决策风险不是少一个榜单，而是把不兼容的数据平均起来，以及把分账份额误认为换人收益。

### 1.1 必须区分的三个层次

1. **记账正确**：逐击、角色、总池守恒，C# 与独立 Python 实现一致。
2. **模型可信**：参数快照、提供者身份和攻击力公式具有证据；不只看守恒。
3. **决策有效**：同条件多场对照显示队伍目标改善，结论没有被采样和统计偏差制造。

前一层通过，不自动证明后一层成立。

## 3. 统一指标与兼容性契约

### 3.1 不变的数学边界

- totalCredit = baseCredit + selfRuleCredit + assistCredit。
- sum(totalCredit) + unattributedCredit = analyzableDealt。
- totalDamage = analyzableDealt；直接伤害与辅助当量不可相加充当新的总伤害。
- 属性倍率、原生 fold、贡献用 atkadd 虚拟因子分开；不可拿所有贡献因子直接对 knownMult。
- 明确排除项依事件分类，无法解释的差额保留 reconciliationGap。未知攻击者和敌方伤害单列，不当作我方已知排除项。
- 零分母输出不可用及原因；缺数据不伪装成 0 或 100%。
- 覆盖率说明分母，整场覆盖率不能用已分析池内的 creditedShare 替代。

### 3.2 比较资格按指标判断，而不是一枚全局绿灯

建议新增离线 ComparisonEligibility 契约，先不修改既有 schema：

| 指标 | 必需条件 | 不满足时 |
|---|---|---|
| 同队事件域伤害总量 / DPS | 同伤害定义、敌我范围、采集完整性及时间定义；同任务/模式/比较窗口 | 只展示单场，不进入效果排名 |
| 角色总贡献 / 辅助当量 | 上述条件 + 方法与能力集兼容 + 身份可解析 + 对应检查通过 | 分层展示或拒绝合并 |
| 规则覆盖率 | 明确命中加权、伤害加权或时间覆盖，且所需字段存在 | 不把命中覆盖冒充时间持续率 |
| 通关率 / 波次 / 生存 | 结局及进度元数据可信，目标一致 | 标注证据不足，不从总伤害反推胜率 |

特别注意：method 都叫 log-share/1，仍可能因 atkadd 是否采集而能力不同；同版本也可能因配置开关或数据截断而不可比。full 仅描述单场适用性，不等于任意两场可以比较。

“伤害来自游戏”也不自动保证跨版本可比：分析事件集、攻击者识别、丢事件、计时、友伤过滤都可能变化。

- 固定同一事件集和分母，输出现行模型、隔离 atkadd 后回到 base 的敏感性结果，以及有证据支持的替代模型。后两者只进入研究表，不改正式贡献表。

- 评估逐 giver 对账需要什么字段；聚合等式无法排除 A 的贡献被错记到 B。先写最小字段设计，再决定是否增加导出。

**交付**：拟建 ATKADD-MODEL-AUDIT.md、离线敏感性脚本、手算多 giver 用例及真实样本对照。

**验收**：守恒、身份、公式证据分别给结论；证据不足时写“稳定性尚未证实”，只有敏感性实验确实显示排名变化时才写“不稳定”，不得硬选赢家。隔离 atkadd 的实验须明确重分账方法（重新拆池或仅迁回已分出的 atkadd 当量），两者不可混称，也不模拟真实换人。公式语义真要变更时升 method 版本，与 schema 分开。

批量 crosscheck 遇到已知 1.6.0 错误返回非零是正确行为。上层回归汇总可以声明“所有结果符合预期”，但必须同时保留原始 ERROR，严格按指定文件哈希和指定缺陷匹配预期。不能过滤掉所有失败，也不能把原文件修到通过。

### 6.3 插件变更门槛

仅在确需改插件时构建并执行 recon_probe、既有五守卫、贡献单测/闸门/交叉验证，以及变更涉及的布局、开关联动、日志和文档检查。检查清单以实际职责建立，不以“17 项/18 项全绿”的过期计数代替覆盖说明。

部署前核验旧版备份哈希，部署后核验实际 DLL；保留全部历史导出、档案、回滚锚点和崩溃备份。不得回滚到已知崩溃版本。

## 7. 统一任务交付模板

每个智能体必须提交：

1. 任务编号、目标、实际改动范围与未改边界。
2. 输入文件清单及哈希，证据等级：实测 / 离线重放 / 静态审查 / 推断。
3. 修复前失败用例、修复后结果和正常对照。
4. 完整命令、工作目录、退出码、独立结果目录。
5. 每项门槛是否实际执行，不适用/缺数据及原因。
6. 对既有伤害、贡献、schema、方法、历史比较的影响。
7. 未解决问题、未运行测试、需要用户参与的唯一最小事项。
8. 接口依赖、文件所有权及是否可合并；不得自行部署 DLL。

## 8. 阶段完成定义与暂缓事项

### 下一阶段最低完成定义

- 新 1.7.10 样本有独立验收记录，目录快照和状态资料可追溯。
- 比较器会拒绝不合格贡献样本，并区分指标级兼容性。
- 已出场零贡献、缺失、同名冲突、不同能力版本都有测试。
- 当前语料能生成一份含不确定性、限制和证据链的配队报告。
- 高份额 atkadd 辅助至少有模型假设清单和敏感性结果。
- 用户不必为每个假设反复开战；只在正常游玩时合并补充必要证据。

### 明确暂缓

自动推荐“最优阵容”、把移除角色直接模拟为扣掉其贡献、将治疗/控制强行折伤害、训练场与普通关卡统一排名、敌我双方通用贡献支持、大规模重构、未验证的暴击因果归因。

**最终目标不是让贡献比例看起来更精确，而是让用户知道：这套队伍哪里有效、结论有多可靠、下一次换人验证什么，以及什么情况下暂时不应下结论。**
