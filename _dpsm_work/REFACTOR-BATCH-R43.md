# 重构批次记录 R43:MasterDataAccess 抽取设计

方案 §11 要求:先定位调用方并读全上下文,再提取 MasterDataAccess,并保持七条行为
(非泛型集合路径 / 对象判空差异 / 解密读取 / 字段布局验证 / 失败计数 / 加载失败后重试 / 原生对象存活策略)。
RF6a 已完成定位;本轮把七条逐条对应到代码位置,形成可直接执行的抽取设计。本轮不含代码改动。

## 1. 两处的确切位置(本轮复核)

| 路由 | 位置 | 特征 |
|---|---|---|
| 标签路由 | MasterDataNames.cs:292、:329 | 两个泛型方法,约束 MasterTableBase / Il2CppObjectBase |
| 转储路由 | MasterDataDump.cs:389 | Table<TKey,TTable,TRow>,同一组约束,19 个调用点 |

两处共享的正是最微妙的部分:同一组泛型约束、同一套解密读取、同一套空值处理。
差异部分(转储还要逐字段布局、失败计数、重试)必须留在调用方。

## 3. 抽取形状(下一轮执行)

新增 MasterDataAccess,只承担两处真正共享的一件事:用同一组泛型约束、同一套解密与判空,把一张表枚举成键值对。
签名写成 where TTable : MasterTableBase where TRow : Il2CppObjectBase(与现有一致,离线可编译)。
两个路由各自改为调用它,并各自保留自己的判空、布局、计数与重试。

## 4. 为什么本轮不改代码

方案对这类改动的验收要求是实机验证一次真实读取路径。用户这一场已提供活的 masterdata 转储(批次 r42),
但剩余预算不足以同时完成抽取 + 两路逐字段对照 + 差异归零;而半完成的读取路径改动比不改更危险
(出错表现是字段静默错位,不是崩溃)。因此本轮只交设计。

## 5. 下一轮的验证方法

1. 从批次 r42 的转储取每张表的全部键作为对照输入;
2. 新旧两路各自产出键值映射,逐键逐字段比较(类型、字符串、默认值、缺失键行为);
3. 差异必须为 0 才提交;有差异就地回退并写进记录,不顺手修语义;
4. 全程不替换运行中的 DLL;
5. 若两路无法同进程同时运行,则以转储为基准做离线回放。
