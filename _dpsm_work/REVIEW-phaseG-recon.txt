### 2.2 算术模型与验证【离线重放】

对每击,把 comp2 的"增益:"段落解析成:Rate = Σ(攻击力+N%),Actual = Σ(攻击力+N)(含 (参照...) 的也按原值先计入)。
模型:attackPower = B(t) x (1 + Rate/100) + Actual。

常量基座单位给出精确验证:

| 单位 | 文本组 | 攻击力实测 | 反推 B | 命中数 |
|---|---|---|---|---|
| 火砲 | 攻击力+10% | 1971 | 1791.8 | 5 |
| 火砲 | 攻击力+700%、攻击力+10% | 14515 | 1792.0 | 60 |
| クトゥグァ砲台 / 砲台R | 攻击力+10% | 841 | 764.5 | 各 13 |

即 1792 x 1.10 = 1971.2 -> 1971、1792 x 8.10 = 14515.2 -> 14515,整数截断下完全吻合;两个不同文本组反推出的 B 相差 0.01%。
-> 百分比加算是可加的(ΣRate),固定加算是直接相加,基数只乘一次:模型成立。【离线重放,强证据】

角色单位的 B(t) 不是常数,而是缓慢漂移:例如 テトラ 3674->3936(0-93 s,约 +7%)、メアリー 3955->4365(约 +10%)、
ルナリス 1116->1495(约 +34%)。所以"基础攻击力"必须逐击重建,不能一场取一个值。

### 2.3 可解释比例估计【离线重放】

方法(可复现):对每个盟友攻击者,逐击算 B_implied = (attackPower - Actual)/(1+Rate);
取该击 ±3 s 窗口内 B_implied 的 95 分位作为 B(t)(失配以"文本多报"为主 -> B_implied 偏低,故取高分位);
再用 B(t)x(1+Rate)+Actual 预测 attackPower,相对误差 <=1.5% 记为"可重建"。

| 攻击者 | 命中 | 可重建(命中口径) | 可重建(伤害加权) |
|---|---|---|---|
| エヴァラス・フラウ | 187 | 94.1% | 98.6% |
| メルティエル | 345 | 99.1% | 99.8% |
| ルナリス | 42 | 100.0% | 100.0% |
| 火砲 / 两台砲台 | 91 | 100.0% | 100.0% |
| テトラ | 1500 | 79.3% | 86.9% |
| メアリー | 936 | 79.4% | 93.1% |
| ネーフェ＝ジアー | 488 | 74.6% | 80.1% |
| マッドシーカー | 1800 | 57.4% | 74.7% |
| 生ける炎 クトゥグア | 131 | 9.9% | 29.4% |
| 合计 | 5520 | 72.4% | 86.7% |

加算块的规模(同样用上面的 B(t);块 = ((B·Rate + Actual)/attackPower) x 该击 baseCredit):

* 盟友 baseCredit(Σ amount/knownMult)重算 = 46,899,247(字典口径 46,906,191,差 0.015%)【离线重放】;
* 其中落在"可重建命中"上的 = 39,461,382(84.1% of baseCredit);
* 攻击力加算块 ≈ 29,632,189 = 14.54% 的 analyzableDealt = 63.2% 的 baseCredit;
* 其中百分比(Rate)部分 ≈ 64.7 个百分点、固定(Actual)部分 ≈ 2.6 个百分点(以可分析伤害为基);
* 基础攻击力(B)部分 ≈ 9,878,638 = 4.85% 的 analyzableDealt。

-> 结论:加算区确实是唯一还没拆的大块(占总量约 14.5%),值得做;但它整体在 baseCredit(23.0%)之内,拆它不改变任何既有 KPI 定义。

### 2.4 为什么"自身 Buff / 队友 Buff"拆不出来【实测 + 离线重放】

(a) 没有 owner 字段。params 行 = {i,tgt,ty,val,vTgt,vTy,vParam,vRef},没有施加者;comp2 只有文本。
givenApplies 全指向敌人(授予天赋通道)。要在现有导出里区分"谁给的",只能拿数值去撞 actors[].abilities:
例如 ルナリス 的 +20%/+10% 可撞到 クトゥルフの邪神像#10060,+150 撞到 被动:分子の衝撃#20051。
但值是多源同值(9% 同时来自毒の短剣、刻印等),撞库不唯一;且撞不上的一律无法判定是队友还是全局。
-> 任何"自身/队友"拆分都是 heuristic,违反数据字典"无法归因的规则不得静默塞给某人"。【推断风险,高】

(b) comp2 文本与 attackPower 快照不是同一刻读的。硬证据【实测】:
* 同一 (攻击者, 时刻 t, 同一段增益文本) 组内出现不同 attackPower:88 组 / 390 击 = 7.1%(5520 击)。
  例:マッドシーカー t=2.63 同一文本 ...攻击力+150%、攻击力+300(参照ExistenceTime3000%)、攻击力+7%、攻击力+10%,
  三条事件 attackPower=9608,三条=4213(比 2.28)。
* 相邻同刻同文本事件对 3316 对中 83 对 attackPower 不同。
* 另外命中 t=41.9 メアリー 同一秒有 18502 与 3703 两个值(后者 hitType=3/effectId=0,comp1 自带"同威力主档"标注)。
* 既有记录(SESSION-STATE §7.2.29/7.2.31)已说明:攻击力在"攻击开始"取快照,而插件实时读到的 buff 列表/攻击力点位不同刻;
  calc.attackPower 有两条来源:原始快照 与 "同威力主档反推"。

-> 逐条增益按 comp2 拆,会把没生效的增益也算进去;离线只能"检测"(7.1% 的硬矛盾 + 约 28% 偏离平滑基座),不能纠正。
要纠正必须在插件里在 attackPower 快照的同一时刻同时抓增益白名单(以及 owner)。

## 3. 残差研究(Q2)

### 3.a 1.15 规则实际生效次数 —— 可离线定位【离线重放,GO】

方法(闭式,可复现):对一击,
k_folded = calc.fold[] 中 factor ≈ 1.15 的条数;
k_actual = k_folded + round( ln(calc.residual) / ln 1.15 )。
过滤:排除 |residual - critDamageRate/100| <= 1% 的会心带(否则 1.9/1.65 会被误读),排除 residual<0.3(近零残差),要求 |round-x| <= 0.05。
含义:k_actual 就是游戏真正生效的 +15% 份数,拿它和"按状态数应有的份数"对账即可结案。

1.5.5 场结果(5601 击):

| residual 带 | 击数 | 含义(k_actual - k_folded) |
|---|---|---|
| x1.1500 | 24 | 游戏多 1 份(插件少折 1) |
| x1.3225(=1.15 的平方) | 9 | 游戏多 2 份 |
| x0.8696(=1/1.15) | 42 | 插件多折 1 份 |
| x0.7561(=1/1.15 的平方) | 17 | 插件多折 2 份 |
| x0.6575(=1/1.15 的三次方) | 4 | 插件多折 3 份 |

1.5.3 场结果(6269 击):x1.15 17 击;x0.8696 68 击。合计 85 击。
-> 1.5.5 相比 1.5.3,"多折"从 68 降到 42,且出现"少折"33 击;两版合计仅约 100-130 击/场,与 HANDOFF §9c 的"144 击残差"同量级。

与状态数的关系(1.5.5):x1.15 的 24 击中,受击方状态数=2 的 20 击、=1 的 3 击、=3 的 1 击;
x1.3225 的 9 击中,状态数=2 的 7 击、=1 的 2 击。
涉及的 1.15 折叠标签只有:[ド・マリニーの掛け時計] ...それぞれ+15%、[毒の短剣] 毒状態...+15%、
[母なる変異の飛沫] ...それぞれ+15%(全局)、[海魔の残滓] ...それぞれ+15%(全局)。
-> "それぞれ"(按每个匹配状态各 +15%)语义可从编号直接读出:状态数 2 而插件只折了 1 份,残差就正好 1.15。

下一步最小实验(全离线,不需用户配合):把上面的 k_actual 计算固化成一个小脚本(或加进 contrib 的 diagnostics),
对每一场输出 {hits_by_k_actual, hits_where_k_actual != status_count, 涉及规则标签计数};
用 11 份导出一致性检验"状态数 = k_actual"这条规则,产出"1.15 实际生效次数"普查表。
注意:这是"净差",若同一击还有别的未知倍率(如 x2.5 狂気)会串味,所以必须保留 §3.a 的会心/近零过滤。

### 3.b 稳定会心观测通道【现状:NO-GO 离线;需 1 场实机】

* 唯一的会心信号是残差推断:residual ≈ critDamageRate/100。1.5.5 场命中 729 击(reconcile.critInferred=735),
  按 critDamageRate 分布:190->664 击、165->63 击、185->2 击。
* 也就是说:会心已能判真假(729/735 约 99%),缺的不是"判会心",而是"第一方观测"。

通道其实已经存在,且接线完整(只读 src,【实测代码事实】):
Plugin.TryPatchCritProbe()(src/Plugin.cs:136)-> AccessTools.Method(typeof(DamageCalculater), "GetFlyTextNumberSizeForAttack"),
手动打 Postfix;CalcFlyTextSizeHook(src/Hooks/DamageCalculaterHooks.cs:121)拿到 (float attributeRate, bool isCritical, bool isDefenseGreaterThanAttack),

## 5. 风险清单

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 基座 B(t) 用同场数据估 -> 循环性 | §2.3 的比例是上限,不是独立验证 | 要先有"同刻 Buff 快照/基础攻击力"导出,或至少一个"零攻击力加算"的对照击 |
| R2 | comp2 与 attackPower 不同刻(7.1% 硬矛盾,约 28% 偏离平滑基座) | 逐条增益拆分会把未生效增益计入 | 把 7.1% 当已知载体打印;拆分必须给 coverage,不能全覆盖 |
| R3 | BuffParam 无 owner | "自身/队友"拆分只能是启发式 | 字段预留 ownerKey/source,插件侧确认后再填;现在不填 |
| R4 | params 是终局无时刻快照 | 不能逐击使用,易被误用 | schema 里把 params 限定为"对账用",不进贡献计算 |
| R5 | 会心通道"看起来已接好" | 贸然"修"有重演 1.0.48/49 崩溃的风险 | 只加诊断计数器;绝不物化 ActDamage 参数 |
| R6 | 9999 若强行建模 | 会误套普通战斗(计划明令禁止) | 保持 trainingMode 排除 |
| R7 | 1.15 的 k_actual 是"净差" | 与其它未知倍率(x2.5 狂気等)串味会算错份数 | 保留会心带/近零过滤,先按规则标签分组再解释 |

## 6. 复算入口(本次实际用的方法,便于复核)

* 没有新增脚本文件:全部为内存中解析导出的一次性复算。等价命令(用户可自行复跑):
  * python -c "import json;d=json.load(open('BepInEx/plugins/DpsMeter/exports/battle_411001_20261003_235204.json',encoding='utf-8'));..."(注意控制台 GBK,输出请用 ASCII/转义);
  * 或任意 JSON 工具按本节公式复算。
* 关键公式:
  1. B_implied = (attackPower - ΣActual) / (1 + ΣRate/100);
  2. B(t) = 该击 ±3 s 窗口内 B_implied 的 95 分位;
  3. 重建判定:|B(t)(1+ΣRate)+ΣActual - attackPower| / attackPower <= 0.015;
  4. 加算块份额:((B·ΣRate + ΣActual) / attackPower) x (amount / knownMult);
  5. 1.15 实际份数:k_actual = k_folded + round(ln(residual)/ln 1.15)。
