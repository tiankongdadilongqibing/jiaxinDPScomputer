## 2. 接线点

### 2.1 三个候选

| 方案 | 挂点 | 改动面 | 风险 |
|---|---|---|---|
| A(推荐) | 导出结算:ExportService.BuildJson 内调用新 Contribution.AppendJson(sb, s, useFolds) | 新增 1 个 C# 文件 + ExportService 一行 + 2 个 cfg + 版本号 | 低。纯派生,可离线单测;与 CalcReconcile 同构 |
| B | 命中入库:Aggregator.RecordDamage 内 TryGetCompForVictim 之后逐击累加 | Aggregator 会话级累加器 + BattleSession 字段 + 结算清零 | 中。与"汇总从事件派生"纪律冲突;续场与清零点必须成对;要与导出重算逐位相等 |
| C | 折叠发生处:FoldContext.Add 或 BuildChainParts 末尾 | Composition 各文件与 Model/FoldContext | 高。诊断路径重复计(§1.5 第 5 条);把插件逻辑塞进 recon_probe 编译的模型文件;仅配对成功才有 fold |

### 2.2 推荐 A 的调用链

	FinalizeLocked                                   (Aggregator.cs:510)
	  -> ExportService.Export(s)                      (Aggregator.cs:656)
	       -> CalcReconcile.Compute(s)                (ExportService.cs:42,已有)
	       -> BuildJson(s, rec)                       (ExportService.cs:150)
	            -> Contribution.AppendJson(sb, s, useFolds)   <== 新增
	       -> JsonCheck.Validate                      (ExportService.cs:50,已有)
	       -> File.WriteAllText                       (ExportService.cs:51)

Contribution 拆两层,便于离线编译:
* Contribution.Compute(BattleSession s, bool useFolds):纯数据聚合,不引用 Plugin/IL2CPP;
* Contribution.AppendJson(StringBuilder, BattleSession, bool useFolds):手写 JSON。
useFolds 由调用方传 Plugin.CfgReconcileCalc 的取值,使模型文件可被 recon_probe 用 Stubs 编译(§4.3)。

### 2.3 为什么选 A

* 与 CalcReconcile 契约完全一致(源码:CalcReconcile.cs:27-29),汇总不可能与行数据不一致。
* 不动 Aggregator 热路径(每击);导出时一次 O(事件 乘 折叠)= 28369 次循环,可忽略。
* 可离线单测:接口只吃已存内存对象。
* 阶段 F 可复用同一 Compute,不必另写一套。

### 2.4 接线点必须钉死的四个判据

1. 只处理 e.Type == "dmg"(离线同 — aggregate.py:104-108)。
2. 攻击者只由 e.AttackerKey 解析到 team==1 的 actor;不得名字回退(aggregate.py:114-131)。
3. fold 输入 = e.Calc.Valid 且 useFolds 时的 e.Calc.Fold,再按 factor>0、不等于 1、>=1 过滤
   (离线 extract_folds — aggregate.py:47-73)。
4. attributedDamage/totalDamage 由同一轮计算的浮点值给出,不要另算整数版(§3.2)。

### 3.2 数值格式与恒等式

* 金额建议 F4(InvariantCulture)。若只输出整数(long),每个角色独立取整,11 个角色总误差可达正负 5.5,
  会撞穿 crosscheck 的 abs 容差 1.0(crosscheck.py:30-33);F4 总误差小于 1e-3,安全。
* totalDamage/attributedDamage/unattributedDamage 用未取整 double 写 F4,并保证文件内
  Σactors.totalCredit + unattributed == analyzableDealt(离线角色恒等式绝对误差约 1e-6,相对 3.8e-15 — 字典 §10)。
* 所有文本转义走 JsonText.Str(源码:src/Output/JsonText.cs),与全插件同一条规则。

### 3.3 体积取舍

【父代理实测】聚合段 25.9 KB(占 22.9 MB 的 0.116%);逐击 credit 1403.6 KB(6.26%)。

* 【实测】部署 DpsMeter.dll、DpsMeter.dll.1.5.5-verified.bak、src/bin/Release/DpsMeter.dll 三者
  SHA256 均 18E4D933C9C8724090FE276CE5E9F70CD844BF7E5AB038D3B335554691365FA9(340,992 B)。

### 4.5 crosscheck 闸门的不对称(建议补,不阻塞)

* 规则只遍历"插件提供的行"(crosscheck.py:99-110):插件漏报一条规则不会被发现;
* 链接同样只查插件侧(crosscheck.py:113-125);actor 才是双向查(crosscheck.py:80-93)。
建议补"离线有、插件无"的反向断言,否则少报规则能骗过验收。属守卫自身,不属插件改动。

## 5. 开关与失败模式

### 5.1 建议 cfg(沿用现有命名约定 — 源码:src/Plugin.cs:299-328)

	General/Contribution        bool  true   "FEATURE (1.6.0 阶段 E):写 contribution 段(派生量)。off = 1.5.5 结构"
	General/ContributionPerHit  bool  false  "逐击 credit(与 calc.fold 顺序对齐)。实测约 +6.26% 文件体积;默认关"

* "关掉时完全回到 1.5.5 行为":严格说只有结构能回到(不再有 contribution 与逐击 credit);
  根 version 会随 BuildInfo 变成 1.6.0。要数值/结构逐字节等同 1.5.5 只有 §6 回退 DLL。
* 两个开关在 BuildJson 开头取一次快照,不要在循环里读 ConfigEntry。

### 5.2 关键耦合 CfgReconcileCalc

离线核心只读文件里实际存在的 calc.fold;插件读内存。若 General/ReconcileCalc=false:文件无 calc.fold;
离线把所有伤害记基础项(creditedShare 仍可能 1,但规则/关系空);C# 若仍按内存 fold 算即 MISMATCH。
处理(推荐):共用判据 —— Contribution.Compute(s, useFolds),useFolds 取 Plugin.CfgReconcileCalc 的值,
且逐事件仍要求 e.Calc.Valid。非默认配置下两边同样退化为全部基础,crosscheck 仍一致。
在 contribution.diagnostics.knownLimits 写 "ReconcileCalc off => folds unused"。
(备选:Contribution on 时强制发射 calc — 改变 ReconcileCalc 既有语义,风险大,第一版不做。)

### 5.3 失败降级

* 异常:BuildJson 在 Export 的 try 内(源码:ExportService.cs:37-147),Contribution 抛异常会让整场导出失败。
  所以 AppendJson 内部必须自 try/catch:失败时写
  "contribution":{"schemaVersion":"1.0","method":"log-share/1","damageBasis":"dealt","error":"...","evidence":"failed"}。
  这样根键仍存在(1.6.0 形状不被误判缺键),且"没有"与"失败"可区分(与 HITDET/FACT 自报哲学一致)。
* actor 解析失败:逐 fold 落 unattributed[reason],绝不静默回填攻击者或队友(字典 §1.3/§4)。
* 数值退化:M<=0、ln(M)==0、f<=0、f==1、0<f<1 全按离线语义;对 NaN/Infinity 做 IsFinite 检查,
  绝不把 NaN/Infinity 写进 JSON(JsonCheck 只查括号与重复键 — 源码:src/Output/JsonCheck.cs:31-36)。
* 空会话:s==null 或 s.Events==null 时输出 header 加全 0 coverage,不要省略根键。
